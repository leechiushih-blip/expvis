# AI生成忠实度评估 — 评分量表

本文档描述了论文中忠实度评估所使用的结构化评分量表，由三位评分者共同使用。

## 评分者须知

对于每个AI生成的实验，请根据以下四个标准评估实验结构。实验以JSON对象形式加载到ExpVis编辑器中。评分前可在流程画布、属性检查器和全屏预览中查看实验。

## 标准1：阶段结构完整性（0–100%）

实验是否包含所有必需的阶段？阶段是否正确标注类型并按正确顺序排列？

| 得分 | 描述 |
|------|------|
| 100% | 三个阶段均存在（指导语、正式实验、反馈），类型正确，顺序正确 |
| 80% | 三个阶段均存在，但一个阶段命名错误或缺少类型标注 |
| 60% | 仅有两个阶段 |
| 40% | 仅有一个阶段 |
| 0% | 无阶段或完全无结构 |

## 标准2：组件完整性（0–100%）

所有必需的刺激、响应和逻辑组件是否都存在？组件属性是否正确设置？

| 得分 | 描述 |
|------|------|
| 100% | 所有必需组件均存在，属性值正确 |
| 80% | 核心组件均存在，存在次要属性错误（如字号不理想） |
| 60% | 缺少一个重要组件（如试次中无响应组件） |
| 40% | 缺少多个组件或存在重大属性错误 |
| 0% | 不完整或不可用 |

## 标准3：逻辑正确性（0–100%）

随机化、分支、循环和键映射是否正确配置？

| 得分 | 描述 |
|------|------|
| 100% | 所有逻辑组件正确配置，键映射与刺激匹配，分支目标有效，循环次数适当 |
| 80% | 逻辑基本正确，存在次要问题（如分支条件类型不够理想） |
| 60% | 存在一个逻辑错误（如部分变体缺少键映射、分支目标不正确） |
| 40% | 存在多个会影响数据质量的逻辑错误 |
| 0% | 逻辑根本性错误 |

## 标准4：总体可用性（1–5 Likert量表）

该实验能否直接在数据收集中使用，或仅需极少修改？

| 得分 | 描述 |
|------|------|
| 5 | 可直接使用，无需任何修改 |
| 4 | 仅需微小调整（如微调字号、补充指导语细节） |
| 3 | 需要适度调整（如修复一个逻辑组件、补充缺失试次） |
| 2 | 需要大量调整（如重构阶段、修复多个逻辑错误） |
| 1 | 需要完全重建 |

## 评分程序

1. 通过浏览器控制台将生成的实验JSON加载到ExpVis中
2. 在流程画布中检查阶段和试次结构
3. 逐组件点击，在属性检查器中验证属性值
4. 运行全屏预览以测试交互逻辑
5. 在评分表上记录每个标准的得分

## 注意事项

- 如果实验JSON解析失败，所有得分均为0
- 如果实验加载但全屏预览崩溃，总体可用性上限为2
- 评分者应独立评分，不可相互讨论
